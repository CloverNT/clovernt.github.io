### Packet

SSO 网络包。收到的 `body` 是解密后的明文，发送时也写明文，重加密由下游处理。

    'uin': { type: 'std::string', description: '数字账号，例如 "10001"' },

    },
    'uid': {
      type: 'std::string',
      description: 'NT 账号 id（"u_..."）。',
    },

<Callout type="warn">
  Packet 的内存布局是 ABI 的一部分。  
  新字段原则上**只能追加在末尾**，不能插进中间，否则按旧头文件编译的插件会按错误的偏移读写。
</Callout>

## Events 命名空间

把网络包事件桥接到强类型事件总线时所用到的运行时事件名字符串常量，定义在 `CloverNT::Nt::Events` 里：`kSsoSend`、`kSsoRecv`、`kO3Send`、`kO3Recv`、`kCredential`。

普通插件不会直接用到它们，想**完全接管**这些事件（不通过事件总线订阅）可以直接 `CloverEventSubscribe` 这些名字。

绝大多数插件应该订阅强类型的 [`PacketSendEvent` / `PacketRecvEvent`](/docs/core/api/events) 等。

## 收发

命名空间 `CloverNT::Nt`。这些都是对 CloverLoader 运行时 C 接口的轻封装，所以能在任何线程调用。

### ready()

```cpp
[[nodiscard]] auto ready() -> bool;
```

发包路径是否已经就绪。`false` 表示 CloverLoader 还没有在 `wrapper.node` 内发现 session 被创建。

### credential()

```cpp
[[nodiscard]] auto credential() -> std::optional<Credential>;
```

读取最近一次捕获到的凭据，不触发事件。登录完成之前返回 `std::nullopt`。

<Callout type="error">
  同样是凭据读取接口。使用守则见上面的 [Credential](#credential) 部分。
</Callout>

### send()

```cpp
[[nodiscard]] auto send(std::string_view command, std::span<const std::uint8_t> body)
        -> std::optional<std::uint32_t>;
```

发送一个 SSO 网络包，不等响应。

- 返回值：CloverLoader 从底层路径截到的序列号。**拿到序列号是通常情况，但不保证**。
- 失败：`ready() == false` 或 `wrapper.node` 一侧把这次发送拒绝时返回 `std::nullopt`。

### receive()

```cpp
[[nodiscard]] auto receive(std::string_view command,
                           std::chrono::milliseconds timeout = kDefaultTimeout)
        -> std::optional<Packet>;

[[nodiscard]] auto receive(std::uint32_t seq,
                           std::chrono::milliseconds timeout = kDefaultTimeout)
        -> std::optional<Packet>;
```

同步阻塞直到收到一个匹配的网络包，或者超时。`std::nullopt` 既可能是超时也可能是接口不可用。

- 按**序号**等：返回下一条序号匹配的网络包。
- 按**命令名**等：返回下一条命令名匹配的网络包，适合订阅型推送。

<Callout type="error">
  **阻塞的是调用线程**。
  
  绝不要在 UI 线程、Hook 的 detour、或任何网络包事件的回调里调用。  
  请参见[网络包](/docs/core/guides/packets) 指南里的线程注意事项。
</Callout>

### call()

```cpp
[[nodiscard]] auto call(std::string_view command,
                        std::span<const std::uint8_t> body,
                        std::chrono::milliseconds timeout = kDefaultTimeout)
        -> std::optional<Packet>;
```

`send` 加 `receive` 的组合，最常用的"调用式发送"写法。

能拿到序号时使用序号等响应，拿不到序号时退回按命令名等响应。

它的阻塞语义和 `receive` 一致。

## 完整示例

```cpp
#include <CloverNT/API/Events/EventBus.hpp>
#include <CloverNT/API/Nt/Packet.hpp>
#include <CloverNT/API/Plugin/PluginBase.hpp>
#include <CloverNT/API/Plugin/RegisterHelper.hpp>

#include <thread>

using namespace CloverNT;

class MyPlugin : public Plugin::PluginBase {
public:
    bool load() {
        auto listener = Event::EventBus::getInstance().emplaceListener<Event::CredentialEvent>(
                [this](Event::CredentialEvent&) { onCredential(); });
        return listener.has_value();
    }

    bool unload() {
        if (mWorker.joinable()) {
            mWorker.join();
        }
        return true;
    }

private:
    std::jthread mWorker;

    void onCredential() {
        if (mWorker.joinable()) {
            return;
        }
        // 把阻塞的 call() 派发到工作线程。owner 不用管，jthread 的生命周期由 unload() 控制
        mWorker = std::jthread([this](std::stop_token stop) {
            if (!Nt::ready() || stop.stop_requested()) {
                return;
            }
            const Nt::Bytes body = encodeRequest();
            if (const auto response = Nt::call("SomeService.Call", body, std::chrono::seconds{3})) {
                logger().info("got response: {} bytes", response->body.size());
            } else {
                logger().warn("request timed out or interface unavailable");
            }
        });
    }
};

CloverNT_REGISTER_PLUGIN(MyPlugin)
```
