`CloverNT::Core` 下面是 CloverCore 的内部实现，头文件在 `include/CloverNT/Core/`，**不属于公开 API**，可能随版本改动。

它们能被 `#include` ，但是他们的符号基本都没有被导出，也就是一般不可用。

`CloverNT::Runtime` 是 CloverLoader 的 C 接口封装，在[另一个分区](/docs/loader)里。

<Callout type="info">
  一般不建议调用 CloverLoader，虽然它的 ABI 保持稳定。  
  建议所有的插件都使用 CloverCore 提供的设施，他们更现代化，也更安全。
</Callout>

## 约定

**错误处理用 `Expected<T>`，不抛异常。** 

它是 `std::expected<T, Error>` 的别名，几乎所有可能失败的函数都返回它，并且标了 `[[nodiscard]]`，忽略返回值会得到编译警告。

```cpp
auto result = Memory::findModule("QQNT.dll");
if (!result) {
    logger().error("{}", result.error().message);
    return false;
}
use(*result);
```

`Error` 带着类别、错误码和消息，详见[基础设施](/docs/core/api/core)。

抛异常的只有少数场景，比如 `PluginBase::self()` 在绑定之前被调用。

**头文件会引入 `Windows.h`。** `Macros.hpp` 在 Windows 上直接包含它，大部分公开头文件都会间接带进来。

如果你对于 `min` / `max` 颇有心得，那请在引用它们之前之前定义 `NOMINMAX`。

## 链接

这些 API 的实现都在 CloverCore 的共享库里，Windows 上是 `CloverCore.dll`，Linux 上是 `CloverCore.so`。

Windows 上插件要链接它的导入库，Linux 上不用，因为符号在加载时从进程里已经加载的库里解析。

详见[开发 Native 插件](/docs/core/plugins/native#构建配置)。
