JavaScript 插件能用的 API，都挂在一个叫 `clovernt` 的全局对象上。

`@clovernt/sdk` 是它的类型。

怎么写 JS 插件见[开发 JavaScript 插件](/docs/core/plugins/javascript)。

```ts title="引入"
import { clovernt, definePlugin } from '@clovernt/sdk';
import type { CloverContext, PluginDefinition } from '@clovernt/sdk';
```

`@clovernt/sdk` 没有发布到 npm，它由 CloverCore 的 CI 从 `framework/` 的产物生成，发布在 [clovernt-sdk](https://github.com/CloverNT/clovernt-sdk) 仓库。

你应该用 git 依赖安装，装法详见开发页里的"类型声明"一节。

## clovernt 全局

SDK 导出的 `clovernt` 其实是一个 `Proxy`，每次访问属性都转发给 `globalThis.clovernt`。

所以模块可以在运行时就绪之前被导入，访问属性时才会获取全局。

<Callout type="warn">
  在 CloverCore 之外的环境里（比如单元测试）`import` 不会立刻出错。  
  **但是一访问属性就会抛出**：`@clovernt/sdk: the CloverNT runtime is not available (the clovernt global is missing)`。
  
  写测试的话要自己提供一个假的 `globalThis.clovernt`。
</Callout>

全局对象在不同位置的成员不一样：

  type={{

### deasync

在主进程里，把异步结果同步地拿到。

<TypeTable
  type={{
    'loopWhile(predicate)': {
      type: 'void',
      description: '只要 predicate() 返回真，就一直转动 Node 的事件循环。',
    },
    'await(promise)': {
      type: 'T',
      description: '同步等一个 Promise 完成，返回它的值；被拒绝的话抛出拒绝的原因',
    },
  }}
/>

等待期间事件循环仍在转，别的回调、定时器照常执行，所以它**可以重入**。

能用 `async` / `await` 的地方，不要用它。

## 日志

<TypeTable
  type={{
    CloverLogger: {
      type: 'interface',
      description: 'debug、info、warn、error、fatal，每个收一个字符串',
    },
    LogLevel: {
      type: '{ Debug: 0, Info: 1, Warning: 2, Error: 3, Fatal: 4 }',
      description: '和 C++ 的 LogLevel 一一对应。注意和 CloverLoader C 接口的 CloverLogLevel 不一样。',
    },
  }}
/>

主进程里 `ctx.logger` 的实际类型比 `CloverLogger` 更丰富，还有 `setMinLevel`、`setLogFile` 等，和 C++ 的 `Logger` 对应。

参见[日志](/docs/core/guides/logging)。
