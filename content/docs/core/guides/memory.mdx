## 特征码扫描

没有导出名可用的时候，就得扫特征码。

特征码是一串字节，用空格分隔，用 `?` 表示通配：

```text
48 8B ? CC          ?  代表任意一个字节
48 8B ?? CC         ?? 同上
4? 8B ? CC          ?  可以只通配半个字节：4? 匹配 40–4F
```

每一段（token）只能是 1 个字符的 `?`，或者 2 个字符。

写成别的长度、含有非十六进制字符、或者整个模式是空的，都会报错。

### 扫描

```cpp
const auto hit = Memory::findFirst("QQNT.dll", "E8 ? ? ? ? 48 8B D8");
if (!hit) {
    return false;   // 没找到
}

const auto call = hit.get();                    // 命中的地址
const auto target = hit.rel(1);                 // 把 E8 后面的 rel32 解成绝对地址
```

<TypeTable
  type={{
    'findFirst(module, pattern, options)': { type: 'ScanResult', description: '第一个命中。module 可以是模块名，也可以是 Module 对象' },
    'findAll(module, pattern, options)': { type: 'std::vector<ScanResult>', description: '全部命中。用它来检查特征码是不是唯一' },
    'findFirstInSection / findAllInSection': { type: 'ScanResult / std::vector<ScanResult>', description: '只在模块的某个节区里扫，比如 .text。比扫整个模块快，也更不容易误命中数据' },
  }}
/>

`pattern` 可以是三种东西，对应三种成本：

<Tabs items={['字符串', '运行期 Signature', '编译期 _sig']}>
  <Tab value="字符串">

每次调用都会解析一遍，写起来最方便，用于一次性的查找。

```cpp
Memory::findFirst("QQNT.dll", "48 8B ? CC");
```

  </Tab>
  <Tab value="运行期 Signature">

  先解析成 `Signature`，多次使用。解析失败会返回 `Expected` 的错误，适合特征码来自配置文件的场景。

  ```cpp
  auto sig = Memory::parseSignature(text);
  if (!sig) { /* 格式错误 */ }
  Memory::findFirst("QQNT.dll", *sig);
  ```

  </Tab>
  <Tab value="编译期 _sig">

  在编译期就展开成数组，写错了**直接编译失败**。

  ```cpp
  using namespace CloverNT::Memory::literals;

  Memory::findFirst("QQNT.dll", "48 8B ? CC"_sigv);
  ```

  `_sigv` 返回指向静态存储的视图，`_sig` 返回一个 `std::array`。

  用这两个还有个好处：可读的特征码文本不会留在二进制里。

  </Tab>
</Tabs>

### 怎么写可靠的特征码

- 把会随编译变动的部分换成通配：立即数、相对偏移、栈偏移
- 用 `findAll` 数一下命中几处。命中不止一处的特征码，早晚会挂到错的地方
- 尽量限定在 `.text` 这样的节区里扫
- 特征码不是越长越好，够唯一就行。太长了很难抗版本更新

读写失败时返回错误，不会崩溃而是返回错误。常见的两个错误：`MemoryNotReadable` 和 `MemoryNotWritable`。

写入的目标页不可写时，`writeMemory` 会**临时放开保护，写完再恢复**。所以改代码段不需要你手动改保护，直接写就行。

## 补丁

要改一段代码的字节，别自己 `writeMemory` 然后忘了改回来，你可以用补丁。

补丁会记下原来的字节，卸载时自动还原。

```cpp
// 把 5 字节改成 NOP
auto patch = Memory::createNopPatch(address, 5);
if (!patch) {
    logger().error("{}", patch.error().message);
    return false;
}
mPatch = std::move(patch.value());   // 存起来，析构时会还原
```

<TypeTable
  type={{
    'createPatch(address, bytes, options)': { type: 'Expected<PatchHandle>', description: '把 address 处改成给定的字节' },
    'createNopPatch(address, size, options)': { type: 'Expected<PatchHandle>', description: '改成 NOP。size 不能为 0，ARM64 上必须是 4 的倍数' },
    'PatchHandle::apply()': { type: 'Expected<void>', description: '重新打上补丁。创建时已经是打上的状态' },
    'PatchHandle::restore()': { type: 'Expected<void>', description: '临时还原，补丁依然登记着，之后可以再 apply' },
    'PatchHandle::remove()': { type: 'Expected<void>', description: '永久移除并还原。析构时调用的就是它' },

补丁和 Hook 一样有所有者，卸载插件时会自动还原。

## 页保护

自己拿着裸指针去写内存之前，才需要手动改保护。

`MemoryProtection` 是一组位标志：

<TypeTable
  type={{
    None: { type: '0' },
    Read: { type: '1' },
    Write: { type: '2' },
    Execute: { type: '4' },
    'ReadWrite / ReadExec / ReadWriteExec': { type: '组合值', description: '对应的标志按位或' },
  }}
/>

可以用 `|` 组合，用 `hasFlag(value, flag)` 判断。

<TypeTable
  type={{
    'setProtection(address, size, protection)': { type: 'Expected<MemoryProtection>', description: '改保护，返回改之前的保护值，拿它来还原' },
    'setProtectionRaw(address, size, protection)': { type: 'Expected<void>', description: '改保护，不去查改之前的值。不需要还原的时候用它，少一次查询' },
    'queryProtection(address)': { type: 'Expected<MemoryProtection>', description: '查某个地址当前的保护' },
    'isReadable(address, size = 1) / isWritable(address, size = 1)': { type: 'bool', description: '检查内存是否可读写' },
  }}
/>

```cpp
auto old = Memory::setProtection(address, size, Memory::MemoryProtection::ReadWriteExec);
if (!old) return;

// ... 改内存 ...

(void) Memory::setProtectionRaw(address, size, *old);   // 还原
```

<Callout type="warn">
  `isReadable` 和 `isWritable` 只能说明"检查的那一刻是可读的"。  
  检查完、真正读之前，别的线程完全可能把这页释放掉。  
  虽然它们能挡掉绝大多数野指针，但这不是安全保证，当心竞态。

  改完保护记得改回去，让代码页长期保持可写既危险也容易被发现。
</Callout>

如果你怕读到坏地址就崩，可以把整段包进 `guardVeh`，把访问违例转成可捕获的异常。
