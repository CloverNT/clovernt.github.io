## 前置条件

SDK 本身的 `CMakeLists.txt` 只要求 CMake 3.19，但你的项目还要满足 CloverNT 的工具链约束：

- Clang 或 clang-cl，不能用 MSVC
- C++23+
- 项目自带的 libc++（ABI 命名空间 `__Cr`）

<Callout type="warn">
  **标准库必须和运行时一致。**
  
  CloverNT 在模块边界上传递 `std::string`、`std::vector` 这类类型，混用其他 STL 会有 ABI 问题。

  细节见[工具链要求](/docs/core/getting-started/toolchain)。
</Callout>

## 引入 SDK

<Steps>
<Step>

### 声明依赖

```cmake title="CMakeLists.txt"
include(FetchContent)

FetchContent_Declare(
        CloverLoaderSDK
        GIT_REPOSITORY https://github.com/CloverNT/CloverLoader-Release.git
        GIT_TAG main
        GIT_SHALLOW TRUE
        EXCLUDE_FROM_ALL
)
FetchContent_MakeAvailable(CloverLoaderSDK)
```

</Step>
<Step>

### 链接运行时

```cmake title="CMakeLists.txt"
add_library(my-raw-plugin SHARED main.cpp)

target_link_libraries(my-raw-plugin PRIVATE CloverNT::Runtime)
```

头文件路径和平台宏都由导入目标带过来，不用自己写 `target_include_directories`。

</Step>
<Step>

### 验证

```cpp title="main.cpp"
#include <CloverNT/Runtime/Kernel.h>

void probe() {
    CloverLogWrite(CLOVER_LOG_INFO, "my-raw-plugin",
                   CloverSelfVersion());
}
```

</Step>
</Steps>

这个脚本是幂等的。如果 `CloverNT::Runtime` 已经被别处定义过（比如你同时引入了 CloverCore），它会直接返回，不会重复定义。

## 平台差异

<Tabs items={['Windows', 'Linux']}>
  <Tab value="Windows">

链接的是 `CloverLoader.lib` 导入库，符号在加载时由已注入的 `CloverLoader.dll` 提供。

`CloverNT_KERNEL_CALL` 在这里展开成 `__cdecl`，函数声明默认带 `__declspec(dllimport)`。

  </Tab>
  <Tab value="Linux">

链接的是 `libCloverLoader.so`，它只是一个链接桩，不含实现。

`CloverNT_KERNEL_CALL` 为空，导出宏使用 `__attribute__((visibility("default")))`。

  </Tab>
</Tabs>

## 常见问题

<Accordions>
  <Accordion title="配置时报 no link artifact for ...">

  SDK 只分发它构建过的平台。报错里会写明期望的路径，比如 `lib/windows-arm64/CloverLoader.lib`。

  确认一下 CMake 探测到的架构对不对，例如用 MSVC 生成器时它看 `CMAKE_GENERATOR_PLATFORM`，否则看 `CMAKE_SYSTEM_PROCESSOR`。
  
  交叉编译时这两个值一般会有问题。

  </Accordion>
  <Accordion title="链接时报大量 std:: 符号未定义">

  一般是标准库用错了。检查有没有调用 `target_use_libcxx`，以及编译器是不是 Clang。

  </Accordion>
  <Accordion title="运行时找不到 CloverLoader 动态库">

  这套 SDK 的符号由注入进程的运行时提供，脱离 CloverLoader 启动的进程单独跑是跑不起来的。

  </Accordion>
</Accordions>
