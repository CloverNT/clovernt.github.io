```cpp title="引入"
#include <CloverNT/Runtime/Kernel.hpp>

using namespace CloverNT::Runtime::Kernel;
```

## InlineHook

模板参数 `Sig` 是被挂钩函数的签名，形如 `int(int, const char*)`。

这个类只移动不复制，析构时自动卸载。

```cpp title="示例"
using Target = int(int);

// detour 必须是普通函数，不能捕获状态
InlineHook<Target> gHook;

int myDetour(int value) {
    if (value < 0) {
        return 0;               // 直接短路，不调用原函数
    }
    return gHook.original(value);
}

void install() {
    gHook = InlineHook<Target>::install(moduleBase("QQNT.dll") + 0x1234, myDetour);
    if (!gHook) {
        logError("demo", "install failed");
    }
}
```

<Callout type="warn">
  `detour` 必须是普通函数指针，带捕获的 lambda 转不过去。  
  需要捕获状态请用下面的 `Detour`。
</Callout>

## Detour

`Detour` 接受任意可调用对象，包括带捕获的 lambda。

代价是它需要一个静态的跳板入口。内部为每个签名类型维护一个 64 槽的跳板池，`install` 时分配一个，`reset` 时归还。

detour 的调用签名和 `InlineHook` 不同，第一个参数是原函数的代理：

```cpp
// 对于 Sig = int(int)，detour 的签名是：
//   int (Original<int(int)>& original, int value)
```

<TypeTable
  type={{

      type: 'template <typename D> static Detour install(std::uintptr_t target, D&& detour)',
      description: '安装一个带状态的 hook',
      parameters: [
        { name: 'target', description: '被挂钩函数的地址，传 0 直接返回无效对象' },
        { name: 'detour', description: '任意可调用对象，签名为 R(Original&, Args...)' },
      ],
      returns: '槽位耗尽或底层安装失败时返回的对象 valid() 为 false',
    },
    'Detour<Sig>::reset': {
      type: 'void reset() noexcept',
      description: '卸载并归还槽位。它会先等所有在途调用退出再归还，所以不能在 detour 自己里面调用',
    },
    'Detour<Sig>::valid': {
      type: 'bool valid() const noexcept',
      description: '同样有 explicit operator bool',
    },
    hookDetour: {
      type: 'template <typename Sig, typename D> Detour<Sig> hookDetour(std::uintptr_t target, D&& detour)',
      description: 'Detour::install 的自由函数写法',
    },
  }}
/>

```cpp title="示例"
auto counter = std::make_shared<int>(0);

auto hook = hookDetour<int(int)>(target, [counter](auto& original, int value) {
    ++*counter;
    return original(value);
});
```

跳板池是按签名类型分的，`int(int)` 和 `void(void*)` 各有自己的 64 个槽位。

同一个签名装到第 65 个才会失败，所以正常用不会碰到上限。

<Callout type="info">
  真能让一个函数挂 64 个以上的 hook，那我建议你还是别写代码了。
</Callout>

## Subscription

订阅句柄的 RAII 封装，析构时自动退订。

它内部存了对应的退订函数指针，所以 DLL 加载订阅和事件订阅都能用同一个类型装。

  type={{

      description: '句柄是否有效',
    },
    onDllLoad: {
      type: 'Subscription onDllLoad(CloverDllLoadCallback cb, void* user = nullptr) noexcept',
      description: '订阅模块加载通知',
    },
    onEvent: {
      type: 'Subscription onEvent(const char* name, CloverEventCallback cb, void* user = nullptr) noexcept',
      description: '按事件名订阅',
    },
  }}
/>

<Callout type="error">
  返回值必须接住。

  ```cpp
  onEvent("CloverNT.PacketSend", myCallback);             // 临时对象立刻析构，订阅失效
  auto sub = onEvent("CloverNT.PacketSend", myCallback);  // 正确
  ```

  这两个函数都标了 `nodiscard`，编译器会给警告。
</Callout>
