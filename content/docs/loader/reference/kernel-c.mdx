<PrivateNotice />

`Kernel.h` 是纯 C 接口，不依赖任何 C++ 运行时。

写 C++ 的话建议直接用 [`Kernel.hpp`](/docs/loader/reference/kernel-cpp)。

```c title="引入"
#include <CloverNT/Runtime/Kernel.h>
```

一个典型的用法是这样：

```c
static void* gOriginal = NULL;

static int CloverNT_KERNEL_CALL myDetour(int value) {
    // 先做自己的事，再调用原函数
    return ((int (CloverNT_KERNEL_CALL*)(int)) gOriginal)(value);
}

void install(void) {
    const CloverAddress target = CloverModuleBase("QQNT.dll") + 0x1234;
    const CloverHook hook = CloverHookInline(target, myDetour, &gOriginal);
    if (hook == 0) {
        CloverLogWrite(CLOVER_LOG_ERROR, "demo", "hook failed");
    }
}
```

detour 的签名写错不会有任何编译期提示，运行起来就是栈被破坏。

## 调用约定与导出宏

`Kernel.h` 里的每个函数都带 `CloverNT_KERNEL_API` 和 `CloverNT_KERNEL_CALL` 两个宏。

`CloverNT_KERNEL_CALL` 是调用约定，Windows 上展开成 `__cdecl`，其他平台为空。

你自己写的 detour 和回调也要带上它，否则栈的清理方有可能对不上。

`CloverNT_KERNEL_API` 控制符号可见性，按宏的定义情况切换：

<Tabs items={['Windows', 'Linux']}>
  <Tab value="Windows">

| 定义了什么 | 展开成 |
| --- | --- |
| `CloverNT_KERNEL_EXPORTS` | `__declspec(dllexport)` |
| `CloverNT_KERNEL_STATIC` | 空 |
| 都没定义 | `__declspec(dllimport)` |

  </Tab>
  <Tab value="Linux">

| 定义了什么 | 展开成 |
| --- | --- |
| `CloverNT_KERNEL_EXPORTS` | `__attribute__((visibility("default")))` |
| 都没定义 | 空 |

  </Tab>
</Tabs>

这两个宏是给 CloverLoader 自己构建用的，作为使用方保持默认即可。

SDK 的导入目标已经把平台宏配好，手动定义反而会让符号解析出问题。
