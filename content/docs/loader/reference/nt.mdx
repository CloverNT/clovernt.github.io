`Nt.h` 是 CloverLoader 暴露给 raw 插件的最底层网络包接口。

CloverCore 的 [`CloverNT::Nt`](/docs/core/api/nt) 命名空间就是基于它实现的，Native 和 JavaScript 插件应优先使用那一套。

```c title="引入"
#include <CloverNT/Runtime/Nt.h>
```

<Callout type="error">
  这个接口直接触达账号通信层。**插件不应该在用户不知情的情况下收发网络包或读取登录凭据**。  
  确保使用它之前知道你在做什么。
  
  详细的使用边界见 [网络包指南](/docs/core/guides/packets)。
</Callout>

## 使用前提

- 这些函数只在**登录态就绪**之后可用。之前调用会返回失败。
- 推荐订阅 `packet::credential` 事件（`CloverEventSubscribe("packet::credential", ...)`）作为"就绪信号"，不要一直等 `ready`。
- 所有函数都可在任意线程调用。接收类函数会**阻塞调用线程**直到结果到达或超时。

## 回调

```c
typedef void (CloverNT_KERNEL_CALL* CloverPacketSink)(const uint8_t* data,
                                                      size_t         length,
                                                      void*          user);
```

sink 在接收函数即将返回时被调用一次，`data` 指向当次调用内有效的内存，返回后立即失效。

如果需要跨调用保留，先 `memcpy` 。`user` 原样透传，用来绑定上下文。

超时或失败时 sink **不会被调用**，接收函数返回 `0`。

<Callout type="error">
  **阻塞的是调用线程**。绝不能在 UI 线程、Hook detour 或任何网络包事件回调里调用。  
  UI 线程被阻塞会让 QQ 冻结；Hook detour 和网络包事件回调里调用则会死锁，因为服务端返回的下一条网络包要经过同一个线程。
</Callout>

sink 回调里的 `data` 是完整的字节流形态（CloverCore 侧用 [`Codec::decodePacket`](/docs/core/api/nt#编解码) 反序列化出 `Nt::Packet`）。

字节布局是私有协议，不要依赖它和服务端或旧版本的二进制兼容。

## 凭据

<TypeTable
  type={{
    'CloverPacketCredential': {

    },
  }}
/>

sink 收到的字节流对应 [`CloverNT::Nt::Codec::decodeCredential`](/docs/core/api/nt#编解码) 的输入。

字段：数字 uin、a2、d2、d2Key（16 字节）、uid（`u_...`）。

<Callout type="error">
  **凭据等同于账号的完整控制权**。任何把它写入文件、数据库、日志、通过网络发往任何地方的行为都应被视为恶意。
  
  CloverLoader 不会，也做不到在运行时阻止这些行为。
</Callout>

## 完整示例

```c title="请求 / 响应"
#include <CloverNT/Runtime/Kernel.h>
#include <CloverNT/Runtime/Nt.h>

#include <stdint.h>
#include <stdio.h>
#include <string.h>

static void CloverNT_KERNEL_CALL onResponse(const uint8_t* data, size_t length, void* user) {
    (void) user;
    printf("response: %zu bytes\n", length);
    // data 在回调返回后失效，需要就 memcpy
}

static void CloverNT_KERNEL_CALL onCredential(CloverEvent* ev, void* user) {
    (void) ev;
    (void) user;
    if (!CloverPacketReady()) {
        return;
    }

    const char    command[] = "SomeService.Call";
    const uint8_t body[]    = { /* 请求体 */ };

    uint32_t seq = 0;
    if (!CloverPacketSend(command, sizeof(command) - 1, body, sizeof(body), &seq)) {
        return;
    }
    if (seq != 0) {
        CloverPacketReceiveBySequence(seq, 3000, &onResponse, NULL);
    } else {
        CloverPacketReceiveByCommand(command, sizeof(command) - 1, 3000, &onResponse, NULL);
    }
}

void installPacketPipeline(void) {
    CloverEventSubscribe("packet::credential", &onCredential, NULL);
}
```

把阻塞的 `Receive*` 换到自己的工作线程，或者只在短超时场景使用，避免拖住主线程。
